# 统一控制器没有证明优于固定 TCP

控制器实现及离线一致性复核有证据，但双向 20 Mbps 性能目标未通过。主比较中控制器双向达标 4/153，固定 TCP 为 9/134，固定方向分离为 0/187；不能用“审计通过”替代性能达标。

## 主比较保留完整时间块，辅助中断块另列

[公开数据](data/adaptive-controller.json)保留全部 1,232 次请求，其中 1,209 次校验成功。主比较是两个完整时间块，共 12 个案例、948 次请求、934 次成功；辅助中断块 284 次请求保留但不进入下表。每次会话先下载 8 MiB 再上传 4 MiB，不是同时全双工。

| 模式 | 双向均≥20 会话 | 下载中位 / P10 Mbps | 上传中位 / P10 Mbps | 上传 TX / 成功正文 |
| --- | --- | --- | --- | --- |
| 固定 TCP | 9/134 | 16.36 / 6.79 | 16.95 / 11.33 | 1.053× |
| 固定方向分离 | 0/187 | 32.66 / 20.01 | 14.31 / 8.90 | 1.057× |
| 统一控制器 | 4/153 | 18.78 / 7.12 | 16.42 / 10.42 | 1.039× |

P10 和中位数只使用成功请求；失败仍进入成本分子和失败计数。两组路径、每候选各两个完整比较案例，暴露时间与完成会话数不同；会话数不是独立随机实验样本数。完整链路到最终客户端没有在此测量。

## 控制事件不等于实际切换收益

统一策略使用 60 秒窗口、每方向至少 8 MiB、20 Mbps 目标、15% 改善、3 个含新观测的支持窗口、300 秒驻留及 180 秒样本过期。可靠性优先，缺少有效需求时不推断链路退化；旧会话不迁移，不重放业务正文。

归档有 187 次决策、17 次探索分配、4 次状态变化意图；真正应用到新会话的主路线切换只有 1 次，Q 主模式仅承载 3 个新会话。主动探测为 0，背压减载在实机没有触发。故障回退意图之后没有对应的新主模式会话，不能声称流量回退已通过实机验收。

60 秒有效窗口中，无失败、无超过 5 秒停顿且双向达标的窗口均为 0：固定 TCP 0/20，方向分离 0/20，控制器 0/21。速率按方向活动耗时归一，不是墙钟全双工容量。

## 复核边界

历史独立复核记录了 23 项单元测试、31/31 一致性检查，以及原始分析 JSON 的完全复算相等。这些是当时归档的验证结果，本次仅重算公开字段，不宣称重新执行实机测试、全面安全审计或部署验收。下一步应扩大完整实验单元、验证背压与恢复，而不是从本次数据宣布控制器更优。
