# 两跳完整链路：交付率优先，再比较成本与速度

本轮全部使用 Trojan、可控 TCP 连接使用 BBR 的 TT 候选完成 24/24，网关 TX / 成功文件正文为 1.047，是本轮全部完成的候选中该成本最低者。它是这组短文件样本的统一候选结论，不是所有客户端和业务的全局最优，也不是当前部署状态。

## 矩阵与候选

三个匿名客户端、两个匿名网关、五种候选、上传/下载两个方向、两个时间块，共 120 次实际开始文件的尝试；每次 20 MiB，同一内容并做长度和 SHA-256 校验。[数据](data/full-chain.json)另有 2 个准备阶段记录，独立于 120 次传输分母。

第一位表示客户端至网关，第二位表示网关至源站：T 是 Trojan，H 是不设置 bandwidth 的 Hysteria2 默认模式。TT、TH、HT、HH 的可控 Linux Trojan 公网连接设置 BBR；TTc 的用户段改为 CUBIC，源站段仍为 BBR。容器内回读不证明 macOS 外层公网连接的算法。

## 客户端差异与取舍

client-A 的两条路径 TT 均 4/4，下载中位数约 43.97 / 45.51 Mbps；同客户端 TTc 下载约 6.53 / 5.34 Mbps。client-C 的 TTc 两路径均 4/4，网关加权成本约 1.030 / 1.037，下载中位数约 12.57 / 13.86 Mbps。client-B 的不同方向存在速度与成本取舍，不能用微小样本内成本差异制定永久的逐设备规则。

HY2 候选的失败与额外发送不限于容器客户端。其默认自适应模式仍可出现放大，因而不能把所有问题归结为手动声明过高。但测试轮次、两跳交互、网络时变、文件短和每格仅两个方向重复，均限制普遍推断。

## 结果可证明到哪里

本轮有独立端点计量、测试连接算法回读和历史清理/状态记录；不包括长期连接、并发容量、所有 UDP 业务或云计费校准。速率从应用请求连接到完整交付计算，HY2 可能预建连接，Trojan TLS 建连时机不同。部署决策仍需明确配置支持范围和业务验收；不能把此处的候选比较直接描述为已完成生产切换。
