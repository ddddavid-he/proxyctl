# 文件、UDP 与隔离客户端回退的历史验证

历史集成记录支持三个匿名路径的文件完整性、UDP DNS 和服务重启后的出口一致性。它只描述当时已执行的检查，不能充当当前生产盘点、整机重启验证或长期故障恢复证明。

## 功能回归保留通过条件

[数据](data/integration-checks.json)删除了出口地址、服务路径、版本目录、进程标识和操作命令，只保留比对结果及文件字节数。每路径包含 canary 和激活后的上传/下载四个 20 MiB 文件校验；源站为固定合成测试目标。

| 路径 | 文件通过 | 文件检查数 | Canary UDP | 激活后 UDP | 服务重启后 UDP | 三阶段出口一致 |
| --- | --- | --- | --- | --- | --- | --- |
| gateway-A | 4 | 4 | True | True | True | True |
| gateway-B | 4 | 4 | True | True | True | True |
| gateway-C | 4 | 4 | True | True | True | True |

文件源为采样活动连接人为等待约 2 秒，原记录的耗时不能用作独立吞吐基准，因此此处没有生成速度排名。服务重启后未重新跑完整文件矩阵，表中不作扩大解释；也未验证整机重启。

## 失败注入发生在隔离客户端

回退验证正常时选择首选节点，随后只将临时客户端的首选地址指向关闭的回环端口，检查健康检测后选择次选节点。两种场景返回的出口身份相同；原始和缓存旁路读回都为 HTTP 200，内容相等。临时客户端清理和共享节点未变更有归档布尔记录。

这验证的是该客户端候选配置下的回退，不等于共享节点真的发生故障，也不证明切换期间旧连接无损迁移。历史中间的手动选择配置已被后续 fallback 配置替代；公开版只把最终回退验证作为候选行为，不发布生产订阅或恢复命令。

## 下一轮需要补充的检查

若用于新的部署，应另做当前状态盘点、并发、长连接、证书刷新、持久化及业务 UDP 回归。公开数据没有凭据、真实目标或可运行的远程变更入口，不会自动重跑历史操作。
